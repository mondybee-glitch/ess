# Elite Engineering Suite v0.9.0 Candidate

حزمة هندسية تضم **32 مهارة محورية فعلية** مع **74 معرّف قدرة متوافقًا** يُوجّه إلى المهارات المحورية عبر سجل القدرات، وتوجيه حتمي، وتصنيف مستقل لمخاطر المهمة، وموافقات محلية محدودة النطاق، ومشغّل فحوصات مسموح بها، وبصمات للأدلة وسجل أحداث قابل لاكتشاف العبث.

## ما الجديد؟

- إضافة `skill-creation-and-evaluation` لإنشاء المهارات وتطويرها وتقييمها، مع حالات إيجابية وسلبية ومعايير قابلة للملاحظة. لا تُعلن فعالية المهارة دون تشغيل وكيل حقيقي وتسجيل الأدلة.
- إضافة `mcp-server-engineering` لتصميم وتنفيذ واختبار خوادم MCP وأدواتها، بما يشمل المخططات والصلاحيات والنقل والأخطاء والمهل الزمنية والتكامل عبر العميل المقصود.
- تعزيز `browser-e2e-and-test-diagnostics` بأنماط اختبار تطبيقات الويب محليًا باستخدام Playwright، مع الاستكشاف من الحالة المعروضة، والانتظار الصحيح، والأدلة والتنظيف.
- تعزيز `ui-ux-design` بمراجعة تصميمية تركز على المنتج الفعلي، والتميّز المقصود، ونقد الأنماط العامة، والمحتوى المفيد والحركة ذات الغرض.
- توثيق المصدر والترخيص في `references/anthropic-agent-skills-integration.md` و`THIRD_PARTY_NOTICES.md`. لم تُنسخ ملفات مساعدات أو أصول أو المهارات المدفوعة الخاصة بالمستندات من المصدر الخارجي.

تضم الحزمة 32 مجلد مهارة محورية و74 معرّف قدرة محفوظًا للتوافق، إضافة إلى 222 عقد تقييم. ملفات المهارات الأصلية محفوظة لأغراض التتبع في `docs/skill-source-archive/` وليست 74 مهارة نشطة منفصلة. يختبر وضع `fixture-only` وجود العقود وروابطها فقط، ولا ينفّذ وكيل ذكاء اصطناعي؛ لذلك تبقى فعالية الوكيل **غير متحقق منها** حتى تتوفر عمليات فعلية ونتائج ومقيّمات.

اقرأ `RELEASE-NOTES-v0.7.6.md` وحدود الإثبات قبل الاستخدام. الحزمة ليست عازل نظام تشغيل وليست ضمانًا لجاهزية الإنتاج.


## تقييم الوكيل الفعلي

أُضيف `scripts/run_agent_evals.py` لتشغيل حالات التقييم عبر محوّل وكيل متوافق مع JSON، وتسجيل المخرجات والملفات وبصماتها والمهل الزمنية. نجاح العملية لا يعني نجاح المهمة؛ تبقى الجودة غير متحققة حتى يراجعها مقيم مستقل. راجع `docs/agent-evaluation/ADAPTER-PROTOCOL-v1.md`.

## حوكمة إضافة المهارات وتوزيعها (v0.9.2)

عند استيراد مهارة من GitHub أو أي مصدر خارجي، لا تُضاف تلقائياً إذا كانت تغطي قدرة موجودة. يجب فحص الترخيص والأمان، ومقارنتها بالمهارة الحالية على مهام متطابقة، ثم اختيار قرار موثق: دمج تحسيناتها في المهارة الأساسية، أو إضافة مهارة مستقلة ذات نطاق مختلف فعلاً، أو الإبقاء على الحالية، أو العزل، أو الرفض. راجع `docs/skill-governance/SKILL_GOVERNANCE_AND_PLACEMENT.md` وسجل القرار النموذجي. لا يتغير اعتماد الإصدار إلى الإنتاج بمجرد اجتياز فحوص البنية.


## تحديث أمني v0.10.1
- المهام عالية الخطورة تستخدم مساحة عمل للقراءة فقط.
- مشغّل Docker يرفض وسوم الصور القابلة للتغيير ويشترط مرجع صورة مثبتًا ببصمة SHA-256.
- ترقية قواعد التعلّم تتطلب تقرير تقييم موثّقًا بـ HMAC ومربوطًا ببصمة القاعدة ومجموعة الاختبار والنتائج.
- ذاكرة التوجيه تتحقق من القرار المخزّن مقابل سياسة المسارات الحالية وتتجاهل الإدخالات المعدّلة.
- الإصدار ما زال مرشحًا هندسيًا محجوبًا عن الإنتاج حتى اكتمال اختبار Docker الفعلي والمراجعة الأمنية والاختبارات الكاملة.
