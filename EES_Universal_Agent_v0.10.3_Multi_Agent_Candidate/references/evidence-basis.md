# Evidence Basis

This package uses current external references as evidence anchors. These sources inform the workflow but do not certify the package or prove task success.

## Software-engineering agent evaluation

SWE-bench evaluates coding systems on real GitHub issues and reports resolved-task percentages across variants including Verified, Lite, Multilingual, and Multimodal. Use it as one benchmark input, not as proof of general engineering quality. The package therefore also requires project-specific fixtures, regression checks, evidence completeness, and cost/time reporting.

Source: https://www.swebench.com/

## Secure software development

NIST SSDF 1.1 organizes secure development practices into Prepare the Organization, Protect the Software, Produce Well-Secured Software, and Respond to Vulnerabilities. NIST also publishes a generative-AI and dual-use foundation-model community profile. Map security work to applicable outcomes and record evidence rather than claiming certification.

Sources:
- https://csrc.nist.gov/projects/ssdf
- https://csrc.nist.gov/pubs/sp/800/218/final
- https://csrc.nist.gov/pubs/sp/800/218/a/final

## Application security verification

OWASP ASVS provides a basis for testing web application technical security controls and secure-development requirements. Use the version recorded at task time and do not treat a checklist as proof of absence of vulnerabilities.

Sources:
- https://owasp.org/projects/asvs
- https://asvs.owasp.org/

## Agent capability and safety evaluation

The 2026 AI Agent Index describes public agent systems across technical capabilities, autonomy and control, ecosystem interaction, safety/evaluation, accountability, and governance. Its methodology notes that public annotation is not the same as experimental probing. This supports the package rule that documentation and structural checks cannot substitute for executed agent evaluations.

Source: https://arxiv.org/html/2602.17753v1

## Application rule

At every material update, record source URL, version/date checked, claim used, assumptions, conflicts, and which project-specific tests turn the guidance into direct evidence.
